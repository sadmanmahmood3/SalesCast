# 📈 SalesCast

**Sales forecasting & inventory planning for small businesses — built for how people actually shop in Bangladesh.**

Upload your sales history and SalesCast will:

- **Forecast** daily sales for the next 2 weeks to 6 months, per product, with a likely range
- **Find your seasons** — best weekdays, busy months, and how much each festival (Eid, Pohela Boishakh, …) lifts your sales
- **Tell you what to order** — when each product will run out, the latest day to reorder, and how many units to buy
- **Show how accurate it is** — every forecast comes with a backtest against real recent sales

## Why I built this

I run [AROHA](https://arohabd.netlify.app), a small clothing brand selling hoodies and punjabi in Dhaka.
Every season I had the same questions: *How many hoodies should I make before winter? When should I order punjabi before Eid?*
Ordering too little means lost sales; ordering too much means cash stuck in unsold stock.

Generic forecasting tools don't understand that punjabi sales spike in the weeks before Eid,
that hoodies barely sell in June, or that Friday is the busiest day here. So I built a tool that does —
and made it work for any small business's sales file, not just mine.

> **About the demo data:** the built-in demo store uses **synthetic data** shaped like AROHA's catalog
> (generated by `scripts/generate_demo_data.py`), because a young brand doesn't yet have years of history.
> Upload any real sales CSV to analyse an actual business.

## Features

| Tab | What it shows |
|---|---|
| **Overview** | Units, revenue, 30-day trend, daily sales chart, product breakdown |
| **Forecast** | Forecast per product or overall with an 80% range, backtest accuracy, CSV download |
| **Seasonal patterns** | Weekday pattern, monthly pattern, festival "rush" multipliers |
| **Inventory planner** | Enter current stock → status, run-out date, order-by date, recommended order quantity |
| **Data** | What was cleaned from your file and why |

## How it works

**Forecasting.** Two engines:
- **Prophet** (Meta) — learns trend, weekly and yearly seasonality, plus Bangladesh festival effects.
- **Fast built-in model** — a ridge regression on the same kinds of features (trend, weekday, yearly sine/cosine waves, festival-window days). Needs no extra install; also a baseline to compare Prophet against.

Both model `log(1 + units)` so forecasts never go negative and festival effects scale with the business,
with a smearing correction so forecast totals aren't biased low.

**Bangladesh festival calendar.** `data/bd_holidays.csv` lists Eid ul-Fitr, Eid ul-Adha, Pohela Boishakh, Pohela Falgun,
Independence Day and Victory Day with a *shopping window* (e.g. Eid ul-Fitr: 21 days before → 1 day after).
Add rows for your own events (Durga Puja, a sale day, …). Eid dates follow the lunar calendar and can shift by a day — fix them in the CSV if needed.

**Festival lift** compares each festival window with the weeks right around it, so a summer festival isn't
judged against winter sales.

**Inventory.** For each product:
- *Safety stock* = z(service level) × forecast uncertainty over the lead time
- *Reorder point* = forecast demand during lead time + safety stock
- *Order quantity* = forecast demand over (lead time + coverage) + safety stock − current stock

**Accuracy.** The backtest hides the last 28 days, forecasts them, and reports total error and WAPE
(weighted absolute percentage error, which handles zero-sales days).

## Run it locally (Windows)

```bash
git clone https://github.com/sadmanmahmood3/SalesCast.git
cd SalesCast
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

It opens at http://localhost:8501. If `prophet` fails to install, run
`pip install streamlit pandas numpy plotly scikit-learn` instead — the app works with the fast engine.

Run the tests: `pip install pytest` then `python -m pytest`.

## Your data format

One row per sale (or per product per day). Column names can be anything — you match them in the sidebar.

```csv
date,product,quantity,unit_price,channel
2026-01-15,Oversized Hoodie - Black,2,1450,Facebook
```

At least **30 days** of history to forecast; **one full year** to learn seasons and festivals.
Dates like `14/03/2026` are read as day-first by default. A blank template is in `data/sales_template.csv`.

## Project structure

```
app.py                       Streamlit web app (UI only)
core/
  data.py                    load, clean, fill missing days with 0
  forecast.py                Prophet + fast engine, backtesting
  insights.py                weekday / monthly / festival patterns
  inventory.py               reorder point, safety stock, order quantity
  holidays.py                Bangladesh festival calendar loader
data/
  bd_holidays.csv            festival dates + shopping windows (editable)
  demo_sales.csv             synthetic demo store
  sales_template.csv         blank upload template
scripts/generate_demo_data.py
tests/test_core.py
```
